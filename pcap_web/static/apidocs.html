StratusServer Documentation API …

StratusServer v2 — le pcap est l'enregistrement maître de chaque mission (capture passive par CR, sessions par le trafic). Base URL : https://<hôte>:8444 (nginx : /api/streams/*, /api/capture/*, /ws/klv/* → démon de capture ; /live/* → MediaMTX ; le reste → serveur de relecture). CORS ouvert, pas d'authentification (réseau fermé).

Capture (démon stratus2-capture)

EndpointRôle
GET /api/capture/statusétat du sniffer, mode de session, ensembles par CR (mission en cours, indicatif, relais live, silence)
POST /api/capture/{CR}/start · /stopcapture manuelle {"mission":"NOM"} / arrêt (rend la main au mode trafic)
GET /api/streams/{CR}/webrtc-urllive WebRTC (fmv-deck) : whep_url, ice_servers, stream_state, mission_name
GET /api/streams/{CR}/klv · WS /ws/klv/{CR}télémétrie KLV 0601 décodée (≤ 5 Hz) : position, cap/attitude, altitude, FOV, portée, centre image, coins, indicatif, pression → FL
GET /api/streams/auto-record/active-mission/{CR} · /sessionsmission en cours (404 = aucune) — compat sensor-tracker
GET /api/streams/eventsSSE : auto_record_started / auto_record_stopped par CR
GET /api/missions/recordings?search=CRnliste compat (mission-launcher) : is_active, duration_seconds, has_metadata, total_size_mb

Missions (serveur de relecture)

EndpointRôle
GET /api/missions?cr=&callsign=&from=&to=&day=captures avec mission.json (CR, indicatif, capteur, début/fin UTC, flux, recent, closed) — filtres CR / indicatif / fenêtre / jour
GET /api/mission/resolve?name=pcap maître d'une mission
GET /api/missions/{m}/detailspoints, début/fin, durée, centre, emprise, taille (compat mission-launcher)
GET /api/missions/{m}/gpx/merged · /download/{m}/gpxtrajectoire GPX 1.1 (positions KLV, 1 pt / 0,5 s, ele, time)
GET /api/missions/{m}/track.geojson · /api/streams/{CR}/track.geojsontrace plateforme (LineString [lon,lat,alt] + times ms) — mission / CR en cours
GET /api/snaps/{m}/list · /file/{f} · POST /processed/{f}snaps du partage MASTER MISSION (widget snaps-import)

Suivi (relecture, DVR, direct) — un suivi par mission, partagé

EndpointRôle
POST /api/follow/start{pcap, watch, track:{profile}, taps} → ouvre ou rejoint le suivi (id, joined)
GET /api/follow/status?id= · /timeline · /delta?cot=&dw=&tr=&k=rattrapage, ligne de temps (dwells, pistes, positions KLV, couverture 4609/4607), ajouts
POST /api/follow/follow · /stopflux vidéo poussés (taps) · détachement (force = arrêt)
GET /api/follow/list · /track.geojson?id=suivis actifs · trace du suivi
WS /ws/video?dport=&follow=MPEG-TS poussé au bord du direct
GET /video.ts?follow=&dport=&from=TS relu depuis le disque à partir de l'instant (retour arrière, Range par octets cumulés)
GET /replay?mission=NOM[&live=1]page opérateur (carte | vidéo | barre de temps)

GMTI 4607 (tracker de référence PCAP_tools)

EndpointRôle
WS /ws/gmti/{CR}snapshot à la connexion, puis gmti (~4 Hz : plots, dwells, pistes, contacts) et status (1 Hz) — contrat du service v1
GET /api/gmti/ports · /status · /{CR}/stateports 4607 par CR, état, instantané
GET|PUT /api/gmti/{CR}/profile · POST /{CR}/resetprofil / surcharges à chaud, remise à zéro des pistes
GET /api/gmti/profiles · POST /api/gmti/profiles/reload · PUT /api/gmti/profilesdépôt partagé gmti_profiles.json (console, processor Java)

Console pcap (analyste) — /console/

Analyse de pcap, rejeu + émission UDP/TCP, écoute réseau, banc de réglage du tracker GMTI, oracle de parité Java. Endpoints /api/streams, /api/flows, /api/klv, /api/timeline, /api/gmti/decode|track, /api/replay/*, /api/live/*, /ws/events — documentés dans le README de PCAP_tools.
