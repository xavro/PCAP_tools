Architecture

RÉSEAU (multicast / unicast UDP par CR)                  Base URL : https://<hôte>:8444  (nginx)
  4609 MPEG-TS+KLV ──┐                                    /api/streams/*, /api/capture/*, /ws/klv/*  → stratus2-capture
  4607 GMTI       ──┼──▶ stratus2-capture (AF_PACKET, passif)  /live/*                                → stratus2-mediamtx
  (CoT : ignoré)  ──┘      │ CAPTURE_SETS=CR1:6789+5454,…      le reste (pages, /api/…, /ws/gmti, /ws/video) → stratus2-replay
                           │ sessions par le trafic (SILENCE_S) : 1er paquet ▶ mission, silence ▶ clôture
                           ├──▶ recordings/{YYYYMMDD_HHMMZ_CRn}/Capture/*.pcap  (segments, index .idx, mission.json)
                           ├──▶ relais TS → MediaMTX (udp://127.0.0.1:2000n) ──▶ WebRTC (fmv-deck, < 1 s)
                           └──▶ télémétrie KLV décodée (≤ 5 Hz) ──▶ WS /ws/klv/{CR}  (sensor-tracker, FlightLevel)

  stratus2-replay (pcap_web) : lit le pcap (en cours ou terminé) — un suivi par mission, partagé
                           ├──▶ /replay (page opérateur) · widget ExB stratus-replay
                           ├──▶ /ws/video (TS poussé au bord du direct) · /video.ts?from= (retour arrière)
                           ├──▶ /ws/gmti/{CR} (tracker de référence, plots / dwells / pistes)
                           └──▶ GPX, détails, track.geojson, snaps, ligne de temps décodée (.tl.jsonl)

Pas de FFmpeg, pas de HLS, pas de base SQL : tout est rejoué depuis le pcap. Réseau fermé : CORS ouvert, pas d'authentification.

● Capture stratus2-capture

Démon de capture passive : un ensemble de ports par CR, ouverture / clôture automatique des missions selon le trafic (aucun ordre GeoEvent nécessaire).

GET/api/capture/statushealth, pages, auto-follow

État du sniffer et des ensembles par CR : mission en cours, ports, dernier paquet, indicatif, relais live, silence.

Réponse

 "sets":{"CR1":{"ports":[6789,5454],"mission":"20260828_1840Z_CR1","callsign":"REAPER01","idle_s":0.2,
                "relay":{"port":20001,"pkts":184201}},
         "CR2":{"ports":[6790,5455],"mission":null,"idle_s":null}}}
POST/api/capture/{CR}/startmanuel

Démarre une capture manuelle sur le CR (nom de mission libre). Corps : {"mission":"NOM"} — sinon nom canonique YYYYMMDD_HHMMZ_CRn.

POST/api/capture/{CR}/stopmanuel

Clôture la mission en cours (écrit closed dans mission.json) et rend la main au mode trafic.

⚡ Live WebRTC & télémétrie KLV stratus2-capture · stratus2-mediamtx

Le TS 4609 est relayé (en-tête RTP retiré) vers MediaMTX ; la vidéo live est servie en WebRTC (WHEP) pour le widget fmv-deck. La télémétrie KLV est décodée par le démon pour sensor-tracker.

GET/api/streams/{CR}/webrtc-urlfmv-deck

URL WHEP du flux live et serveurs ICE (TURN stratus2-coturn ou externe).

{"whep_url":"https://<hôte>:8444/live/cr1/whep","ice_servers":[{"urls":"turn:<hôte>:3478","username":"…","credential":"…"}],
 "stream_state":"active","mission_name":"20260828_1840Z_CR1"}
GET/api/streams/{CR}/klvsensor-tracker, health

Dernière télémétrie KLV 0601 décodée (404 si aucun flux). Noms de champs identiques à ceux publiés jadis par GeoEvent.

PrecisionTimeStamptag 2 (µs UTC) · age_s : ancienneté
SensorLatitude / Longitude / TrueAltitudetags 13, 14, 15
PlatformHeading / Pitch / Rolltags 5, 6, 7
SensorRelativeAzimuth / Elevation, HFOV / VFOV, SlantRangetags 18, 19, 16, 17, 21
FrameCenterLatitude / Longitude, Corner…1-4tags 23, 24, 26-33 (coins, ou 82-89)
PlatformCallSign, PlatformTailNumber, MissionID, ImageSourceSensortags 10, 4, 3, 11
PressureAltitudeFt, FlightLeveltag 37 → altitude pression (ISA par tranches) → FL ; sinon FL calculé sur l'altitude GEO/MSL (repli)
WS/ws/klv/{CR}sensor-tracker

Même objet poussé à ≤ KLV_RATE_HZ (5 Hz par défaut) à chaque nouveau paquet KLV. Le socket reste ouvert entre deux missions (aucun message = aucun flux).

⇄ Compatibilité widgets ExB stratus2-capture

Contrats hérités de la v1, conservés pour sensor-tracker et mission-launcher sans modification côté ExB.

GET/api/streams/auto-record/active-mission/{CR}sensor-tracker

Mission en cours sur le CR — {"mission_name","started_at","cr"}, 404 si aucune.

GET/api/streams/auto-record/sessionssensor-tracker

Toutes les sessions actives (une par CR).

SSE/api/streams/eventssensor-tracker

Événements auto_record_started / auto_record_stopped ({cr, mission_name}) + ping toutes les 15 s.

GET/api/missions/recordings?search=CRnmission-launcher

Liste des captures au format v1 : name, is_active, start_time, duration_seconds, has_metadata, total_size_mb, cr.

GET/api/streams/{CR}/track.geojsonsensor-tracker (ficelle live)

Trace plateforme de la mission en cours (LineString [lon, lat, alt] + times ms) — servie par le serveur de relecture depuis le suivi système.

▤ Missions & captures stratus2-replay

GET/api/missions?cr=&callsign=&from=&to=&day=page Missions, widget stratus-replay

Captures du dossier des enregistrements, les plus récentes d'abord. Filtres : CR, indicatif, fenêtre UTC (epoch) ou jour YYYYMMDD.

{"missions":[{"name":"20260828_1840Z_CR2","cr":"CR2","callsign":"REAPER01","sensor":"EO","start_utc":1787942400.1,"end_utc":1787948210.4,
  "flows":{"6790":1839210,"5455":4120},"bytes":1932441088,"segments":2,"recent":false,"closed":true}]}
GET/api/mission/resolve?name=page opérateur, widget

Pcap maître (premier segment) et métadonnées d'une mission par son nom.

GET/api/missions/{m}/detailsmission-launcher

Points, début / fin, durée, centre, emprise, taille — calculés depuis le journal de la ligne de temps (ou le pcap).

GET/api/missions/{m}/gpx/mergedmission-launcher, page Missions

Trajectoire GPX 1.1 (positions KLV du capteur, 1 point / 0,5 s, ele, time). Alias : /api/download/{m}/gpx.

GET/api/missions/{m}/track.geojsonwidgets

Trace plateforme de la mission (GeoJSON LineString + times).

GET/replay?mission=NOM[&live=1][&profile=]page opérateur

Carte | vidéo | barre de temps. live=1 : suit le bord du direct (DVR) ; sans : ouverture en pause au début. ?pcap=/chemin accepté aussi.

▶ Suivi : relecture, DVR, direct stratus2-replay · un suivi par mission, partagé

Un suivi lit le pcap d'une mission (en cours d'écriture ou terminé), décode KLV / GMTI, alimente la ligne de temps et pousse la vidéo. Plusieurs visionneurs rejoignent le même suivi ; le serveur en ouvre un automatiquement (« système ») pour chaque mission en cours (AUTO_FOLLOW=1).

POST/api/follow/startpage opérateur, widget

Ouvre ou rejoint le suivi. Corps : {"pcap":"…","watch":true,"track":{"profile":"defaut"},"taps":[6790]}. Réponse : {"id","joined","catching_up"}.

GET/api/follow/status?id=page opérateur, widget

Position, vitesse, pause, rattrapage, durée, nombre de paquets, bord du direct.

GET/api/follow/timeline?id= · /api/follow/delta?id=&cot=&dw=&tr=&k=barre de temps

Ligne de temps décodée (dwells, pistes, positions KLV, couverture 4609 / 4607 par seconde) puis ajouts incrémentaux depuis les curseurs donnés. closed signale la fin de mission.

POST/api/follow/followpage opérateur, widget

Déclare les flux vidéo poussés (taps) pour ce visionneur ; from pour repositionner (retour arrière / saut).

POST/api/follow/stoppage opérateur, widget

Détache le visionneur ; le suivi s'arrête quand le dernier part (force : arrêt immédiat, sauf suivi système).

GET/api/follow/list · /api/follow/track.geojson?id=health, widgets

Suivis actifs (mission, CR, durée, abonnés GMTI, système) · trace plateforme du suivi.

▦ Vidéo MPEG-TS stratus2-replay

WS/ws/video?follow={id}&dport=mpegts.js (page opérateur, widget)

TS binaire poussé au rythme du suivi (direct ou relecture) — décodé dans le navigateur par mpegts.js ; le KLV (PID data) est extrait côté client pour la synchro carte.

GET/video.ts?follow={id}&dport=&from={epoch}retour arrière

TS relu depuis le disque à partir de l'instant demandé grâce à l'index (.idx, points vidéo 0,5 s) ; Range par octets cumulés — un saut de plusieurs heures reste instantané.

✂ Clips stratus2-replay · {mission}/clips/

Extrait MPEG-TS d'un créneau UTC, découpé dans le pcap maître par l'index (copie octet à octet, sans FFmpeg). Avec métadonnées : PID KLV conservé + CSV des positions ; sans : paquets KLV retirés. Les clips apparaissent sur la barre de temps de la page opérateur (lane « clips », menu clic droit).

POST/api/clips/extractpage opérateur

Corps : {"mission","start_utc","end_utc","name"?,"include_metadata":true,"dport"?} (epoch UTC ; durée ≤ CLIP_MAX_S, 3600 s par défaut ; nom [A-Za-z0-9_-], sinon clip_HHMMSSZ-HHMMSSZ). Réponse : le sidecar {name, file, start_utc, end_utc, duration, bytes, metadata, csv, klv_pid}.

GET/api/clips/{m}/listpage opérateur, widgets

Clips de la mission (sidecars .json), triés par début — aussi présents dans /api/follow/timeline (clips).

GET/api/clips/{m}/{fichier}[?inline=1]téléchargement

{name}.ts, {name}_klv.csv, {name}.json — en pièce jointe sauf inline=1.

POST/api/clips/{m}/{name}/deletepage opérateur

Supprime le clip et ses sidecars.

◎ GMTI STANAG 4607 temps réel stratus2-replay · tracker de référence PCAP_tools

Le tracker (Python, parité avec le processor Java) tourne dans le suivi système de chaque mission en cours et publie plots, dwells et pistes — même contrat que le service GMTI v1 pour le widget gmti-live-isr.

WS/ws/gmti/{CR}gmti-live-isr

snapshot à la connexion, puis gmti (~4 Hz : plots, dwells, pistes, contacts) et status (1 Hz : ports, paquets, âge).

GET/api/gmti/ports · /api/gmti/status · /api/gmti/{CR}/statewidget, health

Ports 4607 par CR, état global, instantané complet d'un CR.

GET|PUT/api/gmti/{CR}/profile · POST /api/gmti/{CR}/resetconsole

Profil et surcharges appliqués à chaud au tracker du CR (GMTI_PROFILE par défaut) ; remise à zéro des pistes.

GET/api/gmti/profiles · POST …/reload · PUT /api/gmti/profilesconsole, processor Java

Dépôt partagé gmti_profiles.json (volume /data/gmti) : lecture, rechargement, publication depuis la console.

▦ Import snaps stratus2-replay · partage MASTER MISSION

Résolution du dossier : {MISSIONS_PATH}/*/*/{label}/{SNAPS_SUBDIR} — même contrat que la v1 pour le widget snaps-import.

GET/api/snaps/{m}/listsnaps-import

Images en attente : {"mission","path","files":[{"name","size","mtime"}]} (404 si la mission n'a pas de dossier).

GET/api/snaps/{m}/file/{f}snaps-import

Contenu de l'image (type MIME selon l'extension).

POST/api/snaps/{m}/processed/{f}snaps-import

Archive l'image dans {SNAPS_PROCESSED_SUBDIR} (suffixe _vN en cas de collision).

▣ Console pcap (analyste) /

Analyse de pcap, rejeu + émission UDP/TCP, écoute réseau, banc de réglage du tracker GMTI, oracle de parité Java. Endpoints /api/config, /api/streams, /api/flows, /api/klv, /api/timeline, /api/gmti/decode|track, /api/replay/*, /api/live/*, /ws/events — documentés dans le README de PCAP_tools.

▥ Fichiers d'une mission

{recordings}/{YYYYMMDD_HHMMZ_CRn}/Capture/
  {mission}_001.pcap …   segments pcap maître (jamais supprimés ; taille max par segment SEGMENT_MB)
  {mission}.idx          index STRIDX01 (points vidéo 0,5 s, paquets applicatifs, octets cumulés) — ouverture instantanée
  {mission}.tl.jsonl     journal de la ligne de temps décodée (h/c/d/m/t/p/v/k/f : dwells, pistes, positions KLV, flux)
  mission.json           CR, ports, début / fin UTC, flux, indicatif / tail / Mission ID / plateforme / capteur (KLV), closed
{recordings}/{mission}/clips/
  {name}.ts · {name}.json · {name}_klv.csv   clips extraits (créneau UTC, avec / sans KLV)
